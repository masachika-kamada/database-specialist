# ロック

* 別トランザクションにより更新が上書きされることを防ぐ
* 別トランザクションはロックが開くまで待ち続ける

## ロックの種類

* 共有ロック: 他のトランザクションは参照だけ許可
* 専有ロック: 他のトランザクションは許可しない

## ロックの粒度

* テーブルロック: テーブル全体をロック
* 行ロック: 特定の行だけをロック

## 実際のコード

```text
postgres=> start transaction;
START TRANSACTION
postgres=*> lock table 販売管理.商品 in access share mode;
LOCK TABLE
postgres=*> select * from 販売管理.商品 limit 1;
 商品コード | 商品種別コード | 商品名 | 単価 | 最終入荷日 | 型番 | 割引価格
------------+----------------+--------+------+------------+------+----------
          1 |              1 | 鉛筆   |  120 | 2024-07-07 | A    |       84
(1 行)


postgres=!> update 販売管理.商品 set 商品名 = 'pencil' where 商品コード = 1;
ERROR:  current transaction is aborted, commands ignored until end of transaction block
```

エラーが発生した時点で *current transaction is aborted* とのことで、トランザクションが中断されてしまう<br>
PostgreSQL では、ロックのかけ方は以下

* 共有ロック: `LOCK TABLE <テーブル名> IN ACCESS SHARE MODE;`
* 専有ロック: `LOCK TABLE <テーブル名> IN EXCLUSIVE MODE;`

ロックがかかった状態で、別のトランザクションから更新を試みると、待機が発生する<br>
ロックの解除: トランザクションの終了（`COMMIT;` または `ROLLBACK;`）
